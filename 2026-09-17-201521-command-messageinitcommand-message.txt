     │                                                                         │
     │ The three findings that shape the build                                 │
     │                                                                         │
     │ 1. The ring buffer cannot survive real resolution. It holds decoded     │
     │    rgb24                                                                │
     │    frames: 15 s at 2304×1296 is ≈ 4 GB per camera. It becomes a buffer  │
     │    of                                                                   │
     │    encoded H.264 packets (≈ 40 MB/camera), remuxed rather than          │
     │    re-encoded at                                                        │
     │    clip extraction.                                                     │
     │ 2. decode: nvidia has never run. infra/ingest.dockerfile builds on      │
     │    python3.12-bookworm-slim with no CUDA or NVDEC-capable ffmpeg, and   │
     │    the code                                                             │
     │    only sets options["hwaccel"] = "cuda" — it would fall back to        │
     │    software                                                             │
     │    silently. Running analysis natively on the box sidesteps this for    │
     │    the demo;                                                            │
     │    fixing the Dockerfile is a recorded follow-up.                       │
     │ 3. CameraConfig has no credential field. The Imou safety code and the   │
     │    Dahua                                                                │
     │    credentials would land in plaintext YAML in git.                     │
     │                                                                         │
     │ ---                                                                     │
     │                                                                         │
     │ Decisions to record before the code (ADRs)                              │
     │                                                                         │
     │ Written first, not as retrospective justification — AGENTS.md §3.       │
     │                                                                         │
     │ - ADR-0010 — face recognition → ACCEPTED (b), embedded library.         │
     │   InsightFace                                                           │
     │   buffalo_l ONNX bundle (SCRFD-10g detector + w600k_r50 ArcFace         │
     │   embedder),                                                            │
     │   loaded through the existing registry and hash-pinned in               │
     │   models/registry.yaml. Must record explicitly: the insightface code is │
     │   MIT                                                                   │
     │   but the pretrained weights are published for non-commercial research  │
     │   use.                                                                  │
     │   This is acceptable for a demo and is not acceptable for the pilot.    │
     │   The ADR                                                               │
     │   carries an expiry naming the swap (a commercially licensed embedder)  │
     │   as a                                                                  │
     │   blocker on M9, so that it cannot quietly become permanent.            │
     │   The same ADR must record a second gap honestly: THREAT_MODEL.md §1    │
     │   makes                                                                 │
     │   liveness/anti-spoofing a requirement of the face decision, and this   │
     │   build                                                                 │
     │   has none. A photo held to the gate camera will pass. The demo         │
     │   mitigation is the                                                     │
     │   one the threat model already names — the gate is supervised in        │
     │   practice — and                                                        │
     │   it is said out loud rather than discovered by a buyer's auditor.      │
     │ - ADR-0012 — violence → ACCEPTED (c), trigger only, no classifier. The  │
     │   queue                                                                 │
     │   is the product.                                                       │
     │ - ADR-0015 — UI → ACCEPTED (a), server-rendered. FastAPI + Jinja2 + a   │
     │   little                                                                │
     │   vanilla JS (MIT/BSD throughout).                                      │
     │ - ADR-0024 — product name → ACCEPTED: Sparrow Vision. Docs and product  │
     │   surfaces only; the argus. import namespace and the ARGUS_ env prefix  │
     │   stay.                                                                 │
     │ - ADR-0027 (new) — camera credentials. Credentials are referenced from  │
     │   config                                                                │
     │   by name and resolved from the environment or a git-ignored secrets    │
     │   file; never                                                           │
     │   literal in a YAML file that is committed.                             │
     │ - ADR-0028 (new) — pre-trigger buffer holds encoded packets. Records    │
     │   the                                                                   │
     │   memory arithmetic and the remux-not-re-encode consequence.            │
     │ - ADR-0029 (new) — PTZ cameras are used at fixed presets. A pan-tilt    │
     │   lens on                                                               │
     │   a doorway with a fixed door line is a latent contradiction            │

     │   §2, §5). The decision: preset locked, plus a reference-frame drift    │
     │   check that                                                            │
     │   raises a flag rather than silently mis-attributing crossings.         │
     │                                                                         │
     │ ADR-0023 (partial-day charging) stays OPEN with its current leaning;    │
     │ the                                                                     │
     │ implementation follows leaning (a) — a non-RESOLVED interval zeroes the │
     │ day.                                                                    │

     │ Part 1 — Ingest: packets, not pixels                                    │
     │                                                                         │
     │ services/ingest/src/argus/ingest/ringbuffer.py                          │
     │                                                                         │
     │ Add Packet alongside Frame:                                             │
     │                                                                         │
     │ @dataclass(slots=True)                                                  │
     │ class Packet:                                                           │
     │     ts_server: datetime                                                 │
     │     pts: int | None                                                     │
     │     dts: int | None                                                     │
     │     is_keyframe: bool                                                   │
     │     data: bytes                                                         │
     │                                                                         │
     │ PacketRing mirrors the existing RingBuffer API (append, earliest,       │
     │ latest, snapshot, __len__, duration-bounded, threading.Lock) and adds   │
     │ packets_from_keyframe_before(start, end) — a playable clip must begin   │
     │ at a                                                                    │
     │ keyframe, so the window is widened backwards to the last keyframe at or │
     │ before                                                                  │
     │ start. RingBuffer stays for the decoded-frame tap, but shrinks to a     │
     │ small                                                                   │
     │ analysis_buffer_seconds (default 2 s).                                  │
     │                                                                         │
     │ services/ingest/src/argus/ingest/streams.py — in _read_stream, append   │
     │ every demuxed packet to the PacketRing, and decode to ndarray only at   │
     │ the                                                                     │
     │ per-camera analysis fps (new CameraConfig.analysis_fps). Decoding still │
     │ happens for every packet — ffmpeg must, to keep the reference chain —   │
     │ but                                                                     │
     │ frame.to_ndarray(format="rgb24") and the fan-out are throttled, and     │
     │ to_ndarray plus retention is what actually costs. Codec parameters are  │
     │ captured                                                                │
     │ once per session into self._codec_ctx so the clip store can build an    │
     │ output                                                                  │
     │ stream without a decode round trip.                                     │
     │                                                                         │
     │ services/ingest/src/argus/ingest/clip.py — ClipStore.extract remuxes:   │
     │ open the output mp4, container.add_stream(template=...) from the stored │
     │ codec                                                                   │
     │ parameters, mux the packet window starting at the keyframe, rebase      │
     │ pts/dts. No                                                             │
     │ re-encode, so extraction is near-instant and clips are pixel-identical  │
     │ to what                                                                 │
     │ the camera sent — which is what ADR-0008 auditability actually wants.   │
     │ Keep the                                                                │
     │ existing frame-encode path as a fallback for sources whose codec        │
     │ parameters were                                                         │
     │ never captured.                                                         │
     │                                                                         │
     │ Memory arithmetic to state in the ADR: 3 cameras × 15 s of 4 Mbit/s     │
     │ H.264 ≈                                                                 │
     │ 23 MB total, against ≈ 12 GB for the current decoded-frame design at    │
     │ Imou                                                                    │
     │ resolution. The decoded analysis tap at 2 s and 6 fps adds ≈ 100        │
     │ MB/camera.                                                              │
     │                                                                         │
     │ Tests: tests/unit/test_ringbuffer.py gains a PacketRing suite (duration │
     │ bounding, keyframe widening, thread safety).                            │
     │ tests/rig/test_rig_ingest.py's                                          │
     │ clip test keeps its contract — a playable mp4 of ≥ 1 s — and now        │
     │ exercises the                                                           │
     │ remux path.                                                             │
     │                                                                         │
     │ ---                                                                     │

     │ Part 3 — The pipelines layer                                            │
     │                                                                         │
     │ packages/argus_pipelines is empty. It gains a small runner plus one     │
     │ module per                                                              │
     │ pipeline. Each pipeline subscribes to an RTSPSource frame queue,        │
     │ samples at its                                                          │
     │ own rate, and writes rows through argus.store. No pipeline imports a    │
     │ backend —                                                               │
     │ they call the registry.                                                 │
     │                                                                         │
     │ runner.py — wires config → sources → pipelines; owns the asyncio task   │
     │ per                                                                     │
     │ pipeline; shared Detector instance across pipelines to keep one copy of │
     │ the                                                                     │
     │ model on the GPU.                                                       │
     │                                                                         │
     │ canteen.py (payroll-adjacent, the critical path) — at ~6 fps: person    │
     │ detection → short-lived single-camera track (centroid + IoU             │
     │ association, no                                                         │
     │ re-ID, tracks die at frame exit) → door-line crossing test gives        │
     │ enter/exit                                                              │
     │ from the sign of the crossing → on crossing, take the best face crop    │
     │ from that                                                               │
     │ track's recent frames → SCRFD → align → ArcFace → 1:N match against     │
     │ face_template → write a doorway_event with person_id (or null),         │
     │ match_confidence, detection_quality, and a clip_ref from a clip         │
     │ extracted                                                               │
     │ around the crossing. Below the identity threshold ⇒ person_id null.     │
     │ Never a                                                                 │
     │ best guess — DATA_MODEL.md §4 "low-confidence match" row.               │
     │                                                                         │
     │ gate.py — the ZKT tap is the trigger, not the camera. On a tap, take    │
     │ the                                                                     │
     │ face crop nearest the tap timestamp within a correlation window, embed, │
     │ compare                                                                 │
     │ 1:1 against that badge holder's templates, and write a gate_event with  │
     │ face_verified ∈ {true, false, no_face}. no_face must never collapse     │
     │ into                                                                    │
     │ false — that distinction is the entire point of the gate pipeline.      │
     │ Separate                                                                │
     │ threshold constant from the canteen one, in config, with a comment      │
     │ saying why                                                              │
     │ they are different problems.                                            │
     │                                                                         │
     │ presence.py — the Dahua bullet, every few seconds: person count and     │
     │ per-region occupied/empty into occupancy_sample. No person_id, no       │
     │ foreign key                                                             │
     │ that could acquire one.                                                 │
     │                                                                         │
     │ violence.py — always-on cheap trigger on the bullet view; on fire,      │
     │ extract                                                                 │
     │ a clip with pre-roll from the packet ring and write a                   │
     │ violence_candidate with                                                 │
     │ review_state = 'pending'. No classifier, no notification, no name.      │
     │                                                                         │
     │ Direction logic is testable before the cameras arrive. The rig          │
     │ manifests                                                               │
     │ already carry labelled ground truth —                                   │
     │ rig/manifests/canteen_door_01.yaml has                                  │
     │ door_line_x: 320 and ten timestamped crossings with directions. That is │
     │ a                                                                       │
     │ ready-made test oracle for canteen.py's crossing detector.              │
     │                                                                         │

     floor that

     aim.py — 160×90 grayscale FFT phase correlation against a stored reference;
     the peak location is the pixel shift. Three consecutive failures ⇒ stop
     emitting
     doorway events and open a stream_gap with new cause aim_changed. A camera
     pointing elsewhere means "we saw nothing", not "nothing happened" — which
     makes
     fail-open automatic rather than remembered. Recalibration is a deliberate
     logged
     command that renders the door line over a fresh frame for a human to
     accept.

     Process split: argus.ingest owns gate + canteen (the identity path);
     services/analysis/ owns the floor camera (presence + violence). Each owns
     its
     own RTSP connections, so there is no cross-process frame transport to
     build.

     Part 4 — Store

     Six migrations rather than one, because apply_migrations hashes each file
     and
     refuses a changed file after it is applied — a mistake then costs one file.
     Occupancy gets its own file so a reviewer sees the whole table on one
     screen.

     0002_clips_and_health.sql   clip, clip_access_log, camera_health
     0003_identity.sql           person, consent_record, face_template,
                                 badge_assignment, enrolment_action
     0004_payroll_derived.sql    pairing_run, dwell_interval, dwell_day,
                                 payroll_line, payroll_line_day
     0005_gate.sql               gate_tap, gate_event, reader_gap
     0006_occupancy.sql          occupancy_sample (alone, deliberately)
     0007_violence.sql           violence_candidate, violence_review_action

     Plus doorway_event gains supersedes uuid and drops the unwritable
     superseded_by, and stream_gap.cause gains aim_changed.

     Constraints that restate the guarantees in the database, so a future
     service
     or a hand-written INSERT cannot violate what the Python refuses:

     check (state = 'resolved' or overage_s = 0)   -- fail-open, SOUL.md
     check (overage_s <= total_dwell_s)            -- TESTING §2 property 2
     check (end_utc is null or start_utc is null or end_utc >= start_utc)  -- 
     property 6

     payroll_line ships with a trigger that rejects any non-null exported_at,
     naming the AGENTS.md §2.1 sign-off in the exception text. Dropping it is a
     migration, which is a diff, which a human reads.

     clip.is_virtual is denormalised at write time, not joined — camera rows are
     mutable and an export refusing virtual footage must not be defeated by
     flipping a
     flag afterwards. clip_access_log is append-only: a system whose premise is
     auditability cannot have an unaudited viewing path.
     face_template.consent_id is
     not null, so enrolling without recorded consent is a constraint violation
     rather
     than a remembered policy. badge_assignment resolves as-of the tap
     timestamp, because badges get reissued.

     camera_health is a mutable cache of SourceStatus (written by the existing
     status_logger, interval dropped 30 s → 10 s). stream_gap stays the
     evidence.
     Without it the UI cannot tell "idle door" from "dead camera".

     NOTIFY only what a live consumer reacts to: gate_tap, gate_event,
     reader_gap, violence_candidate, violence_review_action, and one
     pairing_run_completed per run. Not per-interval or per-sample — one
     recompute would emit thousands.

     Two traps: tests/conftest.py truncates exactly four tables and every new
     table
     must join that list, or state leaks across tests looking like pairing bugs.
     And
     iterating on an applied migration means docker compose down -v, never
     editing
     the file — put that in DEV_SETUP.md before someone loses an afternoon.

     Part 5 — Payroll: the part that gets the full treatment

     argus/payroll/  version.py types.py policy.py normalise.py
                     pairing.py dwell.py overage.py recompute.py

     There is no export.py; its absence is the design, and a structural test
     asserts the package exposes no symbol matching export|csv|sign. Add
     argus-common as a dependency — reimplementing local_day to keep
     dependencies = [] would give two implementations of a day boundary, which
     is
     precisely the bug class DATA_MODEL.md §1 guards against.

     The walk is not per-day. §4 scopes evaluation to one local day and says a
     midnight-crossing interval is RESOLVED attributed to the enter's day; those
     only
     reconcile if INSIDE survives the boundary. Because max_dwell_s (3 h) ≪ 24 h
     an
     interval crosses at most one midnight, so day attribution is total — the
     plausibility ceiling is what makes it well-defined, and that deserves a
     comment
     because someone will propose raising it.

     Precedence (clock anomaly → gap → structural → plausibility → missing clip)
     with the observation that makes it cheap to review: every branch yields a
     non-RESOLVED state and every non-RESOLVED state yields zero overage.
     Precedence changes the label a reviewer sees; it cannot change the money.

     interval_id is uuid5 over (logic_version, policy_fingerprint, person, 
     space, day, enter, exit), not uuid4 — property 4 is determinism, and a
     random id
     forces an exclusion that would hide real nondeterminism.

     PairingPolicy has no day_zeroing field and no shadow-mode field. Making
     the zeroing rule configurable would put AGENTS.md §2.2 semantics behind a
     YAML
     key. It is hard-coded with # ADR-0023 (a) beside it. policy.describe()
     exists
     so every report page prints the allowance in words — that is what makes "2
     minutes,
     stated out loud" a property of the artefact rather than of the presenter.

     Integer seconds throughout. No float ever touches wage arithmetic.

     Tests — tests/payroll/, non-negotiable:
     test_case_table.py with 15 tests named for the §4 rows (14 original plus
     missing_clip), each asserting state, flags, overage and attributed local
     day —
     a test checking only overage passes on a right number reached the wrong
     way.
     test_properties.py with the six TESTING.md §2 properties plus two:
     invariance
     under input permutation (out-of-order arrival is the real case, and it is
     stronger
     than "no ordering produces end < start"), and every resolved interval
     having
     clips on both ends. Plus test_day_boundary.py, test_precedence.py,
     test_determinism.py, test_no_export.py.

     Hypothesis, dev group only. MPL-2.0 — file-level copyleft, no condition on
     software that imports it, not AGPL, and test-only regardless.
     derandomize=True, database=None in CI so a failure is reproducible by

     Part 6 — Gate and ZKT

     gate/taps.py holds the TapSource Protocol (stdlib only); gate/zkt.py is the
     only module that may import the ZK client. The source never stamps ts_utc —
     the service does, from clock.now_utc(), at receipt. Device clock goes in
     ts_reader_reported, audit only.

     ZktTapSource runs both channels: realtime live-capture (low latency, dies
     silently on some firmware) and log polling (durable, seconds late), deduped
     by a
     unique index on (reader_id, badge_id, ts_reader_reported) with
     on conflict do nothing. That is the honest answer for a device whose
     realtime
     channel fails without saying so. Check pyzk's licence before adding it;
     fallback
     is ~200 lines for the four commands actually needed.

     Correlation is by construction, not by matching two streams — the tap names
     the subject, so there is no window to tune and no chance of matching a tap
     to
     someone else's face. That is why 1:1 is a genuinely easier problem than
     1:N. The
     15 s ring buffer already covers the pre-roll: people are captured walking
     up,
     before the tap.

     gate_tap is written before verification, so a crash loses a verification
     result but never the attendance evidence. Outcomes: true, false, no_face
     (clip produced, no face found), not_attempted (no clip, unknown badge, or
     no
     template). Reader unreachable opens a reader_gap, mirroring stream_gap; on
     reconnect, poll the device log back to the gap start and insert recovered
     taps as
     zkt_replay with face_verified = 'not_attempted' — the ring buffer is long
     gone, nothing was compared. Those rows carry the device clock, which is
     weaker
     provenance, acceptable only because gate attendance is not 
     payroll-affecting;
     a canteen doorway event could never be treated this way. The UI badges it.

     SimulatedTapSource is the config default from day one, so ZKT is a swap-in
     and its absence never threatens the demo. tap_source lands in the row,
     rendered
     as a visible chip: a simulated tap must never be able to look like a real
     one.

     Part 7 — Enrolment

     services/enrol/, a CLI — enrolment is the most privileged write in the
     system
     and a CLI needs no auth model, no upload path, and leaves an
     enrolment_action
     row. Subcommands: person add, consent record, enrol from-images|from-rtsp,
     badge assign, list, purge [--expired], --dry-run on everything.

     already past; --by required with no default (a defaulted enrolled_by is not

     Part 8 — Operator console

     services/ui/, FastAPI + Jinja2, all SQL in queries.py, read-only except the
     two writes the UI owns (clip_access_log, violence_review_action). The UI
     imports no argus.payroll — it renders stored rows from a recorded
     pairing_run; recomputing at request time could silently disagree with the
     evidence a dispute would be settled against.

     1. / — camera and reader state from camera_health, plus a 24 h gap
        timeline as a flexbox bar (no chart library).
     2. /canteen — header generated from the stored run, not a template
        constant: SHADOW MODE — nothing here is exported. Allowance 2 minutes 
        (demo;
        production 60). Logic pairing-1.0.0, policy 4f2a91c0…, computed ….
        Flagged rows show 0 with their flags beside them, so fail-open is
        visible
        rather than inferred. Click through to per-interval detail.
     3. /gate — four outcome chips, confidence against its threshold, source
        chip, clip link.
     4. /violence — pending newest-first, inline video with pre-roll, note,
        dismiss/escalate. No auto-dismiss, no score-based hiding, no
        empty-queue-as-
        success framing.

     Clip playback: the clip table is the allow-list ({clip_ref:path} is a
     traversal vector by construction), resolved path asserted under the clips
     root,
     Range support so <video> can seek, and #t=<offset> on the src so the player
     opens at the moment, not at the start of the clip. That one line is the
     difference between "watch a clip" and the under-a-minute audit PLAN.md M7
     asks
     for. Access logged once per (actor, clip) per 60 s — a single seek fires a
     dozen
     Range requests and a log where one viewing is twenty rows is one nobody
     reads.

     Action writes use ... where review_state = 'pending' so a double-click is
     idempotent and two reviewers racing get a 409, not a silent overwrite.
     Opening a
     clip writes a viewed action, which makes dismissal latency computable — a
     median
     near zero is the rubber-stamping signal THREAT_MODEL.md §2 wants visible.

     Auth is per-role passphrase + typed actor name, localhost bind (ADR-0028,
     OPEN).
     It authenticates a role, not a person. Saying so is the requirement;
     pretending
     otherwise is the failure.

     Part 9 — Config and credentials

     CameraConfig gains analysis_uri, analysis_fps, door_line, preset_id.
     AppConfig gains payroll, gate, face, ui sections. The two identity
     thresholds are separate named fields — face.gate_verify_threshold (1:1) and

     exists,

     consequential
     value in the system is how that value eventually gets set by accident.

     config/secrets.env (git-ignored, mode 600, refuses to load if
     world-readable).
     Unknown name ⇒ ConfigError naming the key, never a partially-expanded URI
     that
     leaks into a connect attempt. CameraConfig.__repr__ redacts, and
     upsert_camera writes the un-expanded template, not the resolved URI — that
     column is the most likely real-world leak. A test builds a source with a
     password,
     exercises the failure paths, and asserts it appears nowhere in caplog.

     Zero-cost hardening while in the camera UIs on day 1: a view-only RTSP 
     account
     per camera (which also cannot drive PTZ, solving half of ADR-0029),
     auto-tracking
